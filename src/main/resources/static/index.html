Chrome 154+ / RFC 9901 SD-JWT (2026年10月更新対応)

Chrome メール認証プロトコル

ワンタイムパスワードや確認リンクに依存せず、ブラウザとメールプロバイダ間の暗号署名 (Selective Disclosure JWT) を用いてセキュアかつ即座にメールアドレスを検証するサーバーサイド (Java Spring Boot) 実装です。

メールアドレス確認フォーム

Session Nonce: __SESSION_NONCE__
Verifier Origin: localhost:8080

Chromeが認識する autocomplete="email" 属性が設定されています。

トークンが自動入力されない場合について
Chromeが実際に外部プロバイダと通信してトークンを自動注入するには、Origin Trial 登録 または 起動フラグ が必要です。ローカル環境ですぐに動作確認する場合は、下の「⚡ トークン生成・セット」または「Simulator Lab」をご利用ください。
未取得 (0文字)

Chrome が autocomplete="email-verification-token" の隠しフィールドに注入したトークンがここに同期表示されます。

クイック動作テスト (Simulator Lab) Chrome OT登録なしでも検証可能

組み込みモック発行者 (Mock Issuer) を使用して、本番ブラウザと同一の暗号トークンを生成・注入してテストできます。

    1. RFC 9901 SD-JWT + KB
    
        
    
          トークンは <Issuer-signed EVT>~<Key Binding JWT> のSelective Disclosure
          JWT構造を持ちます。ブラウザが生成したエフェメラル公開鍵 cnf.jwk によりリプレイ攻撃を防止します。
        
    
      
    

      
    
        
    2. 2026年10月更新: kid省略対応
    
        
    
          Gmailなどの一部プロバイダではトークンヘッダーの kid が省略されます。検証サーバーはJWKS内の全候補鍵を反復ループして署名検証を試行するフォールバックロジックを搭載しています。
        
    
      
    

      
    
        
    3. DNS 委任検証
    
        
    
          _email-verification.<domain> のTXTレコード (iss=<host>) を解決し、EVTの
          iss クレームが正当な発行者であるかを暗号的・階層的に検証します。
        
    
      
    

      
    
        
    4. 安全なOTPフォールバック
    
        
    
          Chrome未対応ブラウザやユーザーによる確認スキップ時は、トークンフィールドが空になります。サーバーはこれを検知し、既存のメール送信 (OTP) フローへシームレスにフォールバックします。
